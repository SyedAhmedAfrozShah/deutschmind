# Master Product Requirement Document (PRD): AI Language Progression System

## 1. Core Project Mandate
Build a fully automated, AI-native language learning platform that evaluates and promotes users from Zero (Absolute Beginner) through A1, A2, and B1 proficiency. The system must act as an evaluator and tutor, generating dynamic content without repetition, and enforcing strict exam gateways before level promotion.

## 2. Technical Stack & API Routing Constraints
* Backend: Python 3.11+ using FastAPI.
* Frontend: Next.js (React) or Streamlit/Reflex. Must handle WebRTC/browser-native audio capture and playback.
* Database: SQLite (local persistent state).
* AI API Integration (CRITICAL): Use the Gemini API. You must configure the application to use standard OpenAI-compatible endpoints for API routing (e.g., base_url="[https://generativelanguage.googleapis.com/v1beta/openai/](https://generativelanguage.googleapis.com/v1beta/openai/)") to ensure stable connectivity and prevent broken paths.
* Audio Pipeline: 
  - TTS (Text-to-Speech): gTTS, edge-tts, or browser native Web Speech API.
  - STT (Speech-to-Text): OpenAI Whisper (local/API) or browser SpeechRecognition API.

## 3. CEFR Level Guardrails & Content Constraints
The AI must strictly adhere to these limits when generating any content or exam:

* Level ZERO to A1 (Breakthrough):
  - Vocabulary: Max 500 common words (Greetings, Numbers, Colors, Basic verbs).
  - Grammar: Present Simple, basic pronouns, simple prepositions.
  - Audio: Slow speed (0.75x), maximum clarity.
  - Speaking: 1-2 sentence replies, single words.

* Level A1 to A2 (Waystage):
  - Vocabulary: Max 1,200 words (Shopping, Directions, Routine, Past events).
  - Grammar: Past Simple, Present Continuous, basic Modals (can/should).
  - Audio: Moderate speed (0.9x).
  - Speaking: Full simple sentences, 15-20 second responses.

* Level A2 to B1 (Threshold):
  - Vocabulary: Max 2,500 words (Opinions, Future plans, Work/Study).
  - Grammar: Future forms (will/going to), Present Perfect, basic Conditionals.
  - Audio: Native normal speed (1.0x).
  - Speaking: Sustained speech (30-60 seconds), complex sentence linking.

## 4. Database Schema (SQLite)
Implement the following tables exactly:

CREATE TABLE users (
    user_id TEXT PRIMARY KEY,
    current_level TEXT DEFAULT 'ZERO', 
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE vocabulary_vault (
    vocab_id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT,
    word TEXT,
    definition TEXT,
    cefr_level TEXT,
    mastery_score INTEGER DEFAULT 0,
    FOREIGN KEY(user_id) REFERENCES users(user_id)
);

CREATE TABLE completed_topics (
    topic_id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT,
    category TEXT, 
    topic_summary TEXT,
    FOREIGN KEY(user_id) REFERENCES users(user_id)
);

CREATE TABLE exam_history (
    exam_id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT,
    target_level TEXT,
    written_score REAL,
    vocab_score REAL,
    listening_score REAL,
    speaking_score REAL,
    overall_score REAL,
    passed BOOLEAN,
    feedback_json TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(user_id) REFERENCES users(user_id)
);

## 5. The Promotion Exam Engine (Gatekeeper Logic)
A user cannot access higher-level content until they pass the current level's Promotion Exam. 

Passing Logic:
* Overall score must be >= 80%.
* No single module score can be < 70%.
* Failure results in a JSON-formatted diagnostic report highlighting exact weaknesses.
* Success updates users.current_level in the database.

Module 1: Vocabulary Test (20% Weight)
* Format: 10 dynamically generated fill-in-the-blank questions.
* AI Prompt Rule: Generate a sentence missing a key vocabulary word appropriate for the user's current tier. Provide 4 multiple-choice options. Return in strict JSON.

Module 2: Written Grammar Test (20% Weight)
* Format: 10 sentence correction or conjugation tasks.
* AI Prompt Rule: Provide a sentence with a grammatical error specific to the CEFR level's grammar constraints. The user must type the correct sentence.

Module 3: Listening Comprehension Test (30% Weight)
* Format: TTS audio playback followed by 5 questions.
* Execution: 
  1. AI generates a 3-paragraph narrative/scenario (respecting word limits).
  2. Backend pipes text to the TTS engine.
  3. User listens to the audio (no text is shown on screen).
  4. User answers 5 multiple-choice comprehension questions generated by the AI.

Module 4: Speaking & Pronunciation Test (30% Weight)
* Format: Verbal response to an open-ended prompt.
* Execution:
  1. AI provides a prompt (e.g., "Describe what you ate for breakfast yesterday in detail").
  2. User records audio via frontend.
  3. STT engine transcribes audio to text.
  4. Grading Prompt: Transcribed text is sent to the LLM with this exact system instruction:
     "Evaluate this transcribed speech for a [Insert Level] English learner. Grade the following out of 100 and return strictly as JSON: 1. Grammatical Accuracy, 2. Vocabulary Range, 3. Task Relevance, 4. Fluency (based on sentence structure cohesion). Provide a 2-sentence feedback summary."

## 6. Smart Anti-Repetition Engine
Every time a lesson or exam is generated, the backend must query the completed_topics table.
* Dynamic Context Injection: Append this to every API call:
  "System Directive: Do not generate scenarios involving the following topics as the user has already completed them: [Fetch array from completed_topics]. Ensure 100% novel scenarios."
* Once a user completes a lesson/test, the main theme of that text must be instantly logged into completed_topics.

## 7. Execution Roadmap for Antigravity Agent
Agent, do not build the whole app at once. Execute in these exact sequential phases and ask the user to test the output before moving to the next phase.

* Phase 1 (Foundation): Set up the FastAPI backend, initialize SQLite, and configure the standard OpenAI-compatible API endpoints for the LLM. Test a basic text generation ping.
* Phase 2 (Content Generation): Build the UI shell. Implement the AI prompts for generating daily vocabulary and basic written grammar exercises. Wire up the Anti-Repetition logic.
* Phase 3 (Audio Pipeline): Integrate the TTS library for audio output and STT library for voice input. Ensure the frontend can successfully record mic input and send it to the backend for transcription.
* Phase 4 (The Exam Gateway): Combine all 4 test modules into a single exam flow. Implement the scoring logic (80% pass threshold). Ensure the database updates the user's level upon passing.
* Phase 5 (Polish): Refine the UI, add the diagnostic breakdown screen for failed exams, and load-test the prompts to ensure strict adherence to CEFR level vocab limits.
